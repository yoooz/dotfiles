# Ask Codex

Codex に独立した批判的検討を求め、返答とその根拠を Claude の判断に取り込む。
Codex は読み取りと助言を担当し、最終判断と実装は Claude が担当する。
Codex 自身からは呼び出さない。

## いつ相談するか

明示的に依頼されたときに加え、次の判断では、方針を確定して実装を進める前に能動的に使う:

- アーキテクチャ、公開 API、データモデル、主要な依存関係など、影響が広い・変更を戻しにくい設計判断
- 並行処理、状態遷移、リトライ、部分失敗、権限境界など、複数の制約や失敗条件が絡む実装判断
- 有力な案が複数あり、正しさ・互換性・性能・保守性のトレードオフや前提への不確実性が結論を左右する場面

実装中にこれらの問題が判明した場合も、その判断点で相談する。相談する論点をユーザーに
短く伝えてから呼び出す。自動相談のたびに改めて許可を求める必要はないが、実行環境の
承認フローと、相談を控えてほしいというユーザーの指定には従う。

自明な修正、既存パターンに沿う小さな変更、単なる整形では自動相談しない。
同じ論点は一度にまとめ、再相談は結論に影響する新しい事実や未解決の反論がある場合に行う。

## 相談の準備

Codex に Claude の会話履歴は共有されない。相談文には必要な範囲で次を含める:

- 達成したいこと、ユーザーの制約、答えてほしい問い
- 現在の案、その理由、比較している代替案、迷っている点。案に賛成することを前提にしない
- 成立に必要な前提と未確認事項。Claude の解釈と、ユーザーが実際に指定した制約を区別する
- 対象ファイルの相対パス、関連するコード・差分、確認済みの事実
- 関係するプロジェクト指示。Codex は対象プロジェクトの `AGENTS.md` を自動で読み込む

作業中の差分が必要なら Claude が `git diff` と未追跡ファイルを確認して渡す。
Codex は読み取り専用サンドボックスで動き、ファイルの読み取りや読み取り系コマンドは
実行できるが、書き込みとネットワークアクセスはできない。
秘密情報を含むファイルや不要な会話履歴を相談文へ一括コピーしない。

相談では、前提の誤り、反例・失敗条件、より単純な代替案、将来どの変更で案が破綻するかを
検討してもらう。「この案でよいか」の追認にしない。批判のために問題を作らせず、妥当な案は
妥当と判断し、その条件と根拠を示してもらう。

## 呼び出し

`<SKILL_DIR>` は、この `SKILL.md` があるディレクトリの絶対パスに置き換える。
対象プロジェクトを第1引数、相談文を標準入力で渡す。引用付き heredoc にして、
相談文中のバッククォートや `$()` をシェルで展開させない。

```bash
bash "<SKILL_DIR>/scripts/ask-codex.sh" "/absolute/path/to/project" <<'CONSULTATION'
目的: ...
制約: ...
現在の案: ...
採用理由・代替案: ...
前提・未確認事項: ...
対象ファイル・差分: ...
相談したいこと: ...
CONSULTATION
```

- ローカルの `codex` とその認証を使う。モデルと reasoning effort は `~/.codex/config.toml` の
  設定に従う。ユーザーがモデルを指定した場合は `ASK_CODEX_MODEL` で渡せる。
- 返答は標準出力に最終メッセージだけが出る。Codex の進行ログは失敗時のみ標準エラーに出る。
  CLI の終了コードを維持する。
- reasoning effort が高い設定では数分かかる。Bash の timeout を長め（5分以上）にするか、
  バックグラウンド実行で回収する。同じ相談を重複起動しない。
- 各呼び出しは独立し、Codex のセッションは保存しない（`--ephemeral`）。
  追加質問では前の回答の関連部分と新しい問いを渡す。
- `config.toml` の `notify` フックはそのまま動くため、相談完了時に通知アプリが起動することがある。
- ファイル編集やコマンド実行を Codex に任せる用途は、このスキルの対象外。

## 返答の扱い

Codex の意見をそのまま結論にしない。特に現在の案への強い反論を、対象コードや制約に
照らして確かめ、採用・不採用の理由を説明する。見解が割れた場合は、どの前提の違いから
結論が分かれたかを整理する。ユーザーには「Codex の見解」と「Claude が確認した判断」が分かるように
報告し、重要な指摘にはファイル位置などの根拠を添える。

## 呼び出せないとき

失敗理由を確認してから対処する。スクリプトは Codex セッション内（`CODEX_SESSION_ID` など）や
`ask-claude` 経由で起動された Claude からの呼び出しを再帰防止のため拒否する。
サンドボックス内だけ認証が失敗する場合は、環境の承認フローを使って外側で再実行する。
権限を迂回するフラグは追加しない。外側でも未ログインならユーザーに `codex login` が
必要なことを伝える。利用上限や通信障害で返答を得られないときは、その事実を報告し、
Codex の見解を捏造しない。
